# MCP client architecture

`src/stdio.ts` starts the stdio transport. `src/mcp.ts` registers the tools and
`src/client.ts` calls the Dreamwork API over HTTPS. stdout carries JSON-RPC
frames; diagnostics belong on stderr. The client has no database access.

Most tools come from `packages/assistant-contracts`, which defines their
arguments, outputs, authorization metadata, and documentation. The remaining
tools proxy product API routes. `packages/api-contracts` supplies wire schemas
used to validate API responses and describe MCP outputs.

The API enforces identity, scopes, rate limits, and confirmations. Consequential
actions can return a held result with a confirmation token before execution.
Public browsing works without a key; account operations need the account
holder's agent key or a hosted OAuth session.

The hosted endpoint is a separate service that shares this tool implementation.
Per-session state belongs inside `createMcpServer`; shared source must not read
process environment variables or retain another connection's identity.

`scripts/build.mjs` bundles the contract sources into the CLI while leaving the
MCP SDK and Zod as external dependencies. `scripts/verify-package.mjs` installs
the npm tarball in a clean directory and drives initialize and tools/list.
The source tests also check version consistency, structured outputs, tool
registration, and documentation generated by `scripts/generate-tool-docs.ts`.
