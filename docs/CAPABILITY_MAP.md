# The assistant capability map

Everything the Dreamwork assistant can do, split by who can ask for it.

## The two channels

A **data action** acts on records. It runs on the server, through the same
engine functions and guards the HTTP routes use, and it leaves something
behind: a saved role, an edited cover letter, a queued application, a receipt
row. Nothing about it depends on where the person is standing, so any agent
holding their Dreamwork key can drive it — their own Claude, their own script,
the `@dreamworkhq/mcp` package, a hand-rolled HTTP client.

A **view action** moves and reveals things on a screen the person is looking
at. It opens a page, sets the filter tray, scrolls a card into view, highlights
a block. Nothing durable changes, and there is no result to send back to a
caller who cannot see the page. So view actions exist only where a browser is
attached, which today means our web client, and they are absent from MCP rather
than present and inert.

A handful of data actions are withheld too, for reasons the registry records
one by one. Those are in the second table with the reason beside them.

## Where this comes from

`packages/assistant-contracts` is the source of truth. Each action declares its
kind, its risk, what the executor demands before it runs, and either its MCP
behaviour hints or the reason it is withheld — and `expose: false` without a
reason does not compile.

The tables below are generated from that registry by
`pnpm --filter @dreamworkhq/mcp docs`, and `apps/mcp/test/tool-catalog.test.ts`
re-renders them and fails when the checked-in copy differs. Change the action,
not the table.

## When a new capability ships

A change that adds a user-facing capability says where it lands: an action in
the registry (which puts it in one of these tables), an existing action that
already covers it, or a deliberate no. Writing "not a new capability" is a
complete answer. Nothing automated can see a capability that never became an
action, so this one is on the author and the reviewer; the generator and its
check only keep the map honest about the actions that do exist.
